# MDASHBOARD — مرجع متدولوژی توسعه داشبوردها

این مخزن چارچوب مرجع، قالب‌های استاندارد و ابزار شروع پروژه برای توسعه تکرارپذیر WEB APPهای داشبوردی است.

## شروع سریع
```bash
python tools/dashboard_onboard.py --repo OWNER/REPO
```

ابزار، REPO ورودی را می‌خواند، ساختار آن را با این مخزن مرجع مقایسه می‌کند، شکاف‌ها را نشان می‌دهد، اطلاعات ضروری را به‌صورت مرحله‌ای از مالک می‌پرسد، مشخصات ماشین‌خوان می‌سازد و با مجوز لازم آن‌ها را به REPO مقصد Push می‌کند.

## احراز هویت
برای Push به GitHub، متغیر محیطی `GITHUB_TOKEN` یا `GH_TOKEN` با دسترسی Contents: write لازم است. Token را در کد یا REPO قرار ندهید.

## قواعد محافظتی
- فایل‌های موجود بدون تأیید صریح بازنویسی نمی‌شوند.
- داده یا تصمیم مجهول، مجهول باقی می‌ماند.
- ابزار تولید مشخصات، به‌خودی‌خود به‌معنی پیاده‌سازی یا تست موفق برنامه نیست.
- Push، اجرا و آزمون موفق فقط پس از دریافت نتیجه واقعی گزارش می‌شوند.

## اسناد مرجع
- `docs/METHODOLOGY.md`: قواعد مرجع و مراحل تعریف.
- `docs/OPERATING_WORKFLOW.md`: گردش‌کار عملیاتی.
- `docs/CROSS_PAGE_DATA_INTEGRITY.md`: Gate الزامی یکپارچگی و سازگاری بین صفحات.
- `specs/cross-page-links.json` در پروژه مقصد: رجیستری ماشین‌خوان ارتباط ویجت خلاصه/هشدار با صفحه جزئیات.
- `docs/DECISIONS.md` و `docs/OPEN_QUESTIONS.md` در پروژه‌های مقصد: منشأ تصمیم‌ها و ابهام‌های باز.
- `specs/`: قراردادهای ماشین‌خوان پروژه مقصد.
- `tools/dashboard_onboard.py`: ابزار مقایسه REPO، مصاحبه و ثبت مشخصات.

## اصل مهم
صفحه اول و صفحات جزئیات باید یک تعریف مشترک از KPI، قرارداد داده و فیلترهای مؤثر داشته باشند. هیچ رابطه خلاصه→جزئیات تا وقتی قرارداد و آزمون پذیرش ندارد، برای تأیید نهایی آماده نیست.
