# گردش‌کار عملیاتی ابزار

1. ورودی OWNER/REPO یا URL عمومی GitHub را دریافت کن.
2. metadata و tree شاخه پیش‌فرض را بخوان؛ README، مشخصات، assets، داده نمونه و تست‌ها را در صورت نیاز بررسی کن.
3. REPO مقصد را با استاندارد MDASHBOARD مقایسه کن. فایل‌های معادل موجود را reuse کن؛ ساختار مرجع را کورکورانه کپی نکن.
4. شکاف‌ها را گزارش کن؛ پرسش‌ها را به ترتیب محصول، پوسته، صفحات، ویجت‌ها، داده، KPI، تعامل، زبان و آزمون بپرس.
5. پاسخ‌ها را همراه وضعیت و منشأ ثبت کن. تصمیم تأییدشده را بدون اجازه تغییر نده.
6. پیش از Push، فهرست تغییرات و فایل‌های موجودی که ممکن است تعارض داشته باشند نمایش داده شود.
7. نوشتن با GitHub Contents API انجام می‌شود. فایل‌ها جداگانه commit می‌شوند؛ در شکست جزئی، فایل‌های موفق و ناموفق باید جدا گزارش شوند.
8. JSONها و ارجاع‌های بین صفحات/ویجت‌ها را تا حد توان اعتبارسنجی کن. تستی که اجرا نشده NOT_RUN است.
9. گزارش نهایی شامل مقصد، فایل‌ها، commit SHA، تست‌های واقعی، پرسش‌های باز و گام بعدی باشد.
