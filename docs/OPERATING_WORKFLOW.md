# گردش‌کار عملیاتی ابزار

1. ورودی OWNER/REPO یا URL عمومی GitHub را دریافت کن.
2. metadata و tree شاخه پیش‌فرض را بخوان؛ README، مشخصات، assets، نمونه داده و تست‌ها را در صورت نیاز بررسی کن.
3. REPO مقصد را با MDASHBOARD مقایسه کن؛ فایل‌های معادل را reuse کن و ساختار مرجع را کورکورانه کپی نکن.
4. شکاف‌ها را گزارش کن؛ سؤال‌ها را مرحله‌ای درباره محصول، پوسته، صفحات، ویجت‌ها، داده، KPI، تعامل، زبان و آزمون بپرس.
5. پاسخ‌ها را همراه status و provenance ثبت کن؛ تصمیم تأییدشده بدون اجازه تغییر نکند.
6. پیش از Push، فهرست تغییرات و تعارض فایل‌ها نمایش داده شود.
7. فایل‌ها با GitHub Contents API ثبت می‌شوند؛ در شکست جزئی، موفق/ناموفق جدا گزارش شود.
8. JSON، شناسه‌ها و ارجاع‌های بین صفحات/ویجت‌ها را اعتبارسنجی کن؛ تست اجرا‌نشده NOT_RUN است.
9. پس از تکمیل مشخصات، ماتریس رابطه هر ویجت خلاصه با صفحه جزئیات را بساز و Gate سند `docs/CROSS_PAGE_DATA_INTEGRITY.md` را اجرا کن.
10. Gate باید KPI/نسخه، قرارداد/نسخه، نگاشت فیلتر، کلید رکورد، شمارش/مجموعه رکورد، واحد، تازگی/Snapshot، دسترسی، localization و رفتار navigation را پوشش دهد.
11. در صورت شکست کنترل بحرانی یا وجود ابهام مسدودکننده، وضعیت Gate FAIL/BLOCKED است و تأیید نهایی صادر نمی‌شود. NOT_RUN هرگز PASS نیست.
12. گزارش نهایی شامل مقصد، فایل‌ها، commit SHA، تست‌های واقعی، وضعیت Gate، شواهد، پرسش‌های باز و گام بعدی باشد.
